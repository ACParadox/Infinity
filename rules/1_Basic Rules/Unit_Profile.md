# Unit Profile

“Soldiers” in Infinity are called Troopers and are grouped into Units belonging to each Army.

All members of a Unit have received the same training and have the same Attributes, Skills, and the same basic gear. Each Unit has a Unit Profile with all the data you need to play it.

Example Of Different Units:

Included below is the format for Unit Profiles, to help you become familiar with the terms, Attributes, and all the Profiles’ information.

1. Common Characteristics of the Unit.

2. International Standard Code.

3. Attributes.

4. Common Equipment and Special Skills for the Unit.

5. Name and different combinations of Special Skill, Equipment, and Weapons and the Cost for each Trooper.

6. Peripheral.

All this makes each Unit unique and sets them apart from the rest.

The contents and features specific to each Trooper are shown in different ways:

- Under the Attributes, Equipment and Special Skills common to all Unit options are shown.

- When one of the options of a profile has a Special Skill, it will be shown next to the Trooper's name.

- If one of the options has Equipment, it will be shown in round brackets next to the name or Special Skill. For example: ( Multispectral Visor L2) or Hacker ( Hacking Device ).

- Equipment is separated from BS Weapons by a vertical bar ("|") in the Weaponry and Equipment column.

- Peripherals are separated from Weapons and Equipment by a double vertical bar ("||") in the Weaponry and Equipment column.

- CC Weapons, or special weapons that may be used as BS or CC Weapons, are in the Melee Weapons column.

## Unit Profile - Attributes

Attributes are a series of numeric values that describe the basic capabilities of Troopers and game elements. In game terms, these are used to make Rolls and calculate the success or failure of attempted actions made by Troopers and game elements. For simplicity, Attribute definitions always refer to the term Trooper.

### Unit Profile - Movement (MOV)

The number of inches this Trooper can move with an Order. The MOV Attribute usually has two values, the first one being for the first time the Trooper moves in an Order, and the other one for the second time he moves.

If the Trooper's Unit Profile does not have a number for the MOV Attribute and instead has "-", the Trooper is stationary and immobile, so cannot move under any circumstances.

### Unit Profile - Close Combat (CC)

This conveys the Trooper's prowess in hand-to-hand combat.

### Unit Profile - Ballistic Skills (BS)

This conveys the Trooper's prowess in ranged combat.

### Unit Profile - Physique (PH)

This represents all physical skills, such as strength, dexterity, throwing, dodging...

### Unit Profile - Willpower (WIP)

This represents all mental skills, such as Discover, Doctor, Hacking …

### Unit Profile - Armor (ARM)

This is a numeric value for the Trooper's overall armor. The higher the value, the heavier and more effective the armor is in reducing the damage of enemy attacks.

### Unit Profile - Bio-Technological Shield (BTS)

This is a numeric value for the Trooper's NBC (Nuclear, Biological, Chemical), Nanotechnological, Electromagnetic, and Anti-Hacking protections.

### Unit Profile - Vitality (VITA)

This represents the physical endurance of the Trooper, and how much punishment it can withstand before losing consciousness or dying.

### Unit Profile - Structure (STR)

This alternative to the Vitality Attribute represents the capacity of mechanical Troopers (TAGs, REMs...) or scenery structures to soak up damage before ceasing to function.

### Unit Profile - Availability (AVA)

This indicates the number of Troopers from this Unit allowed in a single Army List.

### Unit Profile - Silhouette (S)

This indicates the three-dimensional volume of the Trooper for game purposes. The value refers to a specific type of Silhouette Template.

### Unit Profile - Support Weapons Cost (SWC)

The cost in Support Weapon Points paid for adding a Support Weapon to a Trooper of that Unit. This value is pivotal when constructing your Army Lists.

### Unit Profile - Cost (C)

This is the value in Army Points of the Trooper with all its Special Skills, Weapons, and Equipment. This value is pivotal when constructing your Army Lists.

Some Unit Profiles might not have a numerical value for one of their Attributes and instead have a "-" symbol. In this the case, they cannot declare or use any Skill that requires that Attribute.

## Unit Profile - Weaponry

In the Combat Module section, you will find all the information needed to use Weapon Charts in Infinity, and in the Weaponry section you will find those weapons that require further explanation.

A Unit Profile is a *rules container*, not just a statline. Every value, Skill, Weapon, Label, and note on the profile is assumed to be always in effect unless explicitly disabled by a State, Scenario rule, or Special Skill.

Attributes shown on the Unit Profile (MOV, CC, BS, PH, WIP, ARM, BTS, W, S, AVA, etc.) are the *base values* before MODs. Any MOD in brackets on the profile only applies when using that specific Skill, Weapon, or Equipment. Bracketed values are not global bonuses.

Training Characteristics (Regular, Irregular) and Troop Type (LI, MI, HI, REM, TAG, etc.) are always active and silently affect many rules (Order generation, Lieutenant eligibility, Engineer/Doctor interactions, Hacking vulnerability). These effects are not restated elsewhere.

If a Unit Profile lists multiple Weapons of the same type, this does not imply simultaneous use. Only one Weapon, Equipment piece, or Attack option is chosen per declared Attack unless a rule explicitly allows otherwise.

SWC and Points are Private Information, but *the presence of Weapons, Equipment, and Skills on a Unit Profile is Open Information*. Opponents are allowed to know what the model can do, just not its cost efficiency.

Availability (AVA) is checked only during Army List creation. Losing models during the game never interacts with AVA and does not restrict effects that generate or replace Troopers unless explicitly stated.

Profiles with multiple Loadouts represent mutually exclusive options. A Trooper never gains access to equipment from another loadout, even if the miniature visually shows it.

Marker States (Camouflage, Impersonation, Holoecho, etc.) do not remove the underlying Unit Profile. The profile still determines Silhouette, ZoC, Weapons carried, and vulnerabilities. The Marker only changes visibility and information access.

If a Unit Profile includes both a Skill and Equipment that modify the same interaction (for example, Mimetism plus Cover bonuses), they stack unless a rule explicitly forbids stacking. There is no general “same source” restriction.

Lieutenant is a Skill printed on the Unit Profile, but its identity is Private Information. However, all *effects* tied to the Lieutenant Order (extra Orders, NCO interaction, Strategos effects) must be applied correctly even if the model is undisclosed.

If a Unit Profile changes due to replacement (Sepsitorized, Mnemonica, Possession, etc.), the new profile fully replaces the old one unless the rule explicitly says attributes or Skills are retained.

Peripherals listed on a Unit Profile are not optional unless stated. If the Trooper is deployed, its Peripherals are assumed to exist and follow all Controller rules, even if not represented physically until relevant.

When a rule refers to “the Trooper’s Unit Profile,” it includes hidden elements such as Special Skills gained from Sectorials or Fireteams, not just what is printed on the Army Builder card.

**[UNOFFICIAL COMMENT]**
If an interaction seems unclear, default to this order of precedence:
1. State effects
2. Explicit Skill text
3. Weapon and Equipment rules
4. Unit Profile baseline values

# Troop Type — Interactions Notes and Unofficial Comments

Troop Type is a classification tag on the Unit Profile that silently interacts with multiple core systems (Orders, Lieutenant eligibility, Hacking, Engineer/Doctor access, Scenario rules). These interactions are rarely restated elsewhere, so Troop Type should always be checked when resolving edge cases.

**[UNOFFICIAL COMMENT]**
## LI – Light Infantry

Light Infantry represents baseline Troopers with no inherent immunities or vulnerabilities beyond what is explicitly listed on their profile. If a rule targets “Infantry” without specifying Medium or Heavy, LI is included by default.

They usually have a single Wound and almost no ARM and usuall 4-4 MOV.

LI Troopers are fully affected by Hacking only if they possess Hackable traits from Skills or Equipment. They are not inherently Hackable simply for being Infantry.

Doctors normally interact most efficiently with LI due to lower ARM and Wound counts, making revival rolls statistically easier even though no rule explicitly states this advantage.

**[UNOFFICIAL COMMENT]**
## MI – Medium Infantry
Medium Infantry sits in an interaction gap: they are Infantry for all purposes, but do not automatically gain the durability assumptions players associate with Heavy Infantry.

They usually have a single Wound but can have medium ARM.

Rules or Scenarios that differentiate between Light and Heavy Infantry may explicitly exclude MI, meaning MI may receive neither benefit nor penalty unless named.

**[UNOFFICIAL COMMENT]**
## HI – Heavy Infantry

Heavy Infantry are almost always Hackable, but this comes from profile traits, not from the Troop Type label itself. The assumption is common, but players should still confirm.

They have by default two Wounds and at least medium to high ARM and usually have 6-2 MOV. The

When rules reference “heavily armored Troopers” narratively, only rules that explicitly say “HI” mechanically apply. Flavor text has no rules weight.

**[UNOFFICIAL COMMENT]**
## REM – Remote

REM Troopers are never eligible to be Lieutenant, regardless of Skills gained later, unless a rule explicitly overrides this restriction.

REM are affected by Engineer instead of Doctor by default. If a rule refers to “Troopers” generically, REM are included unless the rule specifies otherwise. They are also Hackable, but also affected by SupportWare of EVO Hacker.

REM always carry a Repeater to extend the Hacking network.

Sectorials usually have at least these 4 basic REM with 1 STR available:
1) S3 REM Missile bot, that has a Guided BS attack option.
2) S3 REM Flash pulse bot, that is very cheap (good for a cheap regular order).
3) S3 REM Total Reaction bot, usually with a Heavy Machine Gun option.
4) S4 REM Baggage bot, usually with a EVO hacker option and a cheaper plain baggage option.

**[UNOFFICIAL COMMENT]**
## TAG – Tactical Armored Gear
TAGs combine properties of Vehicles, Heavy Infantry–like resilience, and REM-style interactions. Always resolve TAG interactions by explicit rules, never by analogy.

TAGs typically require Engineers for recovery, not Doctors, even if they possess a Wounds Attribute. This overrides intuitive assumptions based on Wounds alone.

When a rule affects “Troopers” broadly, TAGs are included unless Vehicles or TAGs are explicitly excluded.

TAGs are the strongest type in the game, but are Hackable and can be Possessed by the enemy using a Total Control Hack. Make sure to protect the TAG from Hacking.

**[UNOFFICIAL COMMENT]**
## WB – Warband

Warband is a tactical classification, not a mechanical shortcut. It does not automatically imply Impetuous, Irregular, or close-combat focus unless those traits are actually listed on the profile.

Warbands tend to be troops that want to move forward up the field and often have good Close Combat and access to Smoke.

**[UNOFFICIAL COMMENT]**
## SK – Skirmisher

Skirmisher indicates operational role, not deployment method. It does not automatically grant Forward Deployment, Infiltration, or Camouflage unless those Skills are listed.

Many Scenario conditions reference Skirmishers indirectly through Specialist or Deployment Skills; always verify whether the condition keys off the Troop Type or the Skill itself.

Skirmishers tend to be troopers with some kind of capacity to deploey further up the field, to be hidden and/or to have high mobility.

**[UNOFFICIAL COMMENT]**
## VH – Vehicle

Vehicle Troopers are affected by repair and damage rules even when they resemble Infantry or TAGs visually. Troop Type overrides miniature appearance.

If a Vehicle has a Silhouette and behaves like a Trooper, it still follows Vehicle interaction rules first, especially for Engineers, States, and Scenario effects.

Vehicles tend to be fairly rare, they usually cannot use Cover but have high mobility.

**[UNOFFICIAL COMMENT]**
## Peripheral
Peripheral is a Troop Type that is always subordinate to a Controller. It never generates Orders and never exists independently for Order Pool calculations.

If the Controller enters a Null State or is removed, the Peripheral’s behavior is determined entirely by the Peripheral rules, not by its own profile statistics.

Peripherals inherit timing and activation from their Controller, but their Troop Type still matters for targeting, States, and interaction with Templates or Hacking.

When in doubt, resolve Peripheral interactions by asking: “Is this effect targeting the Controller, the Peripheral, or both?” The Troop Type alone does not answer this, but it defines the limits.

For Peripherals types that activate at the same time as the Controller, often one of them will get a Normal roll and the other a Face-to-face roll, since ARO can only target one. 
Also, if both Controller and Peripheral are Specialist, they can roll for a WIP interaction (ex. press a button) twice: one for Controller, one for Peripheral, doubling the chance for success.

# Trooper Classification — Interactions Notes and Unofficial Comments

These classifications describe a Trooper’s *organizational and narrative role*, not direct rules packages. They do not grant automatic Skills, MODs, or immunities unless a rule explicitly references the classification by name. Most interactions are indirect, via Scenarios, Fireteams, AVA, or availability of Specialists and Equipment.

**[UNOFFICIAL COMMENT]**
## Garrison Troopers
Garrison Troopers are typically defensive or area-control units by design, but this is not a mechanical restriction. They may act normally in all phases of the game.

Scenario rules sometimes reference Garrison Troopers implicitly when limiting Forward Deployment, Infiltration, or off-table deployment. Always check whether the restriction keys off *classification* or *Skill*.

Do not assume reduced mobility or training unless explicitly shown on the Unit Profile.

**[UNOFFICIAL COMMENT]**
## Line Troopers
Line Troopers represent baseline trained soldiers and are often used to define the “standard” for AVA, Order generation, and Fireteam composition.

Many Sectorial Fireteam rules key off Line Troopers as mandatory components. This is a list-building interaction, not a gameplay restriction.

Line Trooper status does not imply poor performance. Their efficiency is determined entirely by profile stats and equipment.

**[UNOFFICIAL COMMENT]**
## Specially Trained Troopers
This classification indicates access to niche skills or equipment, not overall superiority. A Specially Trained Trooper may be highly focused and fragile.

Scenario rules may reference these Troopers when limiting access to objectives or granting bonuses to “specialist elements,” but only if explicitly named.

**[UNOFFICIAL COMMENT]**
## Veteran Troopers
Veteran Troopers are often associated with resilience to command disruption or morale effects, but no such protection exists unless a Veteran Skill or equivalent rule is present.

Do not confuse narrative veteran status with the Veteran Special Skill. The two are unrelated unless explicitly linked on the profile.

**[UNOFFICIAL COMMENT]**
## Elite Troopers
Elite Troopers are frequently assumed to be superior in all respects, but this classification has no intrinsic mechanical effect.

Elite status often correlates with higher Points cost, advanced equipment, and rare Skills, which can mislead players into overestimating their durability.

Scenarios may restrict Elite Troopers for balance reasons, especially in low-point or narrative missions.

**[UNOFFICIAL COMMENT]**
## Headquarters Troopers
Headquarters Troopers are commonly associated with command roles, Lieutenants, or support infrastructure, but this is not guaranteed.

Being a Headquarters Trooper does not make a unit a valid Lieutenant, Chain of Command user, or Order modifier unless the Skill is present.

Opponents may infer command importance incorrectly; classification does not equal revealed Private Information.

**[UNOFFICIAL COMMENT]**
## Mechanized Troopers
Mechanized Troopers imply vehicle or transport integration, but deployment methods are determined strictly by Skills such as Mechanized Deployment or Combat Jump.

If a Mechanized Trooper lacks a special deployment Skill, it deploys normally despite its classification.

Scenario rules that limit airborne or mechanized insertion must explicitly reference this classification to apply.

**[UNOFFICIAL COMMENT]**
## Support Troopers
Support Troopers are often Engineers, Doctors, Hackers, or Order enhancers, but the classification itself does nothing mechanically.

Losing Support Troopers can disproportionately affect an army’s functionality, but this is a strategic consequence, not a rules effect.

Support status does not restrict the Trooper from making Attacks or contesting objectives unless stated by the Scenario.

**[UNOFFICIAL COMMENT]**
## Mercenary Troopers
Mercenary Troopers are fully loyal to the Army List they are included in. They are Allies for all rules purposes once selected.

Mercenary classification interacts heavily with Army List building, AVA restrictions, and Sectorial access, but not with in-game alignment.

Do not apply narrative assumptions such as unreliability, morale penalties, or command friction unless a rule explicitly enforces it.

**[UNOFFICIAL COMMENT]**
## Character
Characters are unique by definition. Only one instance of a named Character may be included unless a rule explicitly allows otherwise.

Character status does not automatically grant Veteran protection, elite stats, or immunity to command effects.

Characters frequently anchor Fireteams, unlock special compositions, or alter AVA, but these effects are always stated explicitly.

Killing a Character has no inherent victory condition impact unless specified by the Scenario.

Despite narrative importance, Characters follow the same Order, ARO, and State rules as any other Trooper.
